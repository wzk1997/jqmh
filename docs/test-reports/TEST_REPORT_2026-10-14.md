## 实际发现并修复的问题

| 问题 | 原因 | 修复 |
| --- | --- | --- |
| 本地服务启动时报位置参数错误 | `node:sqlite` 的位置参数需要展开传入 | 统一封装 statement 调用，数组参数使用展开语法 |
| 多个本地游客无法创建 | 空字符串手机号参与普通唯一约束 | 改为仅约束非空手机号的部分唯一索引 |
| 15 位预约码生成越界 | `crypto.randomInt` 区间超过实现上限 | 改用安全随机字节逐位生成 15 位验证码 |
| 管理首页统计无法显示 | 本地 API 返回对象，前端要求统计数组 | 后端改为标准统计数组 |
| 管理首页缺少预约入口 | 首页模块列表未包含 reservation | 增加预约管理入口并指向实际预约后台页面 |
| 反馈图片无法在本地上传 | 仅有云存储路径 | 增加 Base64 校验、本地存储与 `/media` 服务 |
| 预约后台无法写入标准化日期时段 | 缺少本地管理接口 | 增加新增、编辑、详情、列表、状态、排序、推荐和删除保护 |
| 签到缺少时间字段 | booking 只有签到布尔值 | 增加 `checked_in_at` 并兼容已有本地数据库迁移 |
| 空白调试页进入正式包 | `pages/test1/test1` 被注册且缺少配置、样式 | 从正式页面清单和源码中移除 |
| 后台工具页本地接口缺失 | 二维码、用户导出、预约名单导出页面会返回接口不存在 | 补齐 7 个本地路由、真实二维码和 CSV 下载 |
| 预约日历缺参暴露 SQLite 错误 | `list_has_day` 未验证日期 | 增加业务参数校验并返回明确错误 |
| 餐饮、住宿、交通共用商户表 | 只靠 `category` 区分仍有误写风险 | 拆为 `food_merchants`、`stay_merchants`、`travel_merchants`，用注册表和触发器锁定唯一归属 |
