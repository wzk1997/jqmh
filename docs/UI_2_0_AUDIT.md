# WeTravel UI 2.0 页面与功能审计

首页风格已确认，现有业务页面已按同一体系迁移。景区免费开放：用户侧不提供预约、订单、支付、理赔，仅保留客户反馈。原范围仅前端；用户后续明确授权新增客户反馈页面和配套云函数。本轮仅为反馈新增后端路由与数据模型，不修改其他业务接口。审计日期：2026-10-13。

## 首页数据与跳转约束

- 仍请求 `home/list`，参数为 `{}`，加载指示仍使用 `title: 'bar'`。
- 按原 `type` 区分 product、album，补充展示接口原本已返回的 news。
- 精选详情保持 `../../{type}/detail/{type}_detail?id={id}`。
- 静态入口仍使用 `pageHelper.url`；tab 页使用既有 `relaunch` 跳转方式，普通页保留 URL 跳转。
- “景区动态”提示只采用返回内容中明确标为“景区动态”的标题；无匹配时显示“查看景区最新资讯”，不编造公告。
- 无内容、请求失败和重新加载均有对应展示；失败保留已加载内容。
- 摄影沿用仓库现有景区素材，不将庐山样例名称、天气、距离、价格、营业状态或客流数据写成真实业务数据。
- 原首页已有的一处图片内联定位修改，在卡片重构中由统一定位样式替代。

## 导航迁移

目标仍为：首页 / 景区导览 / 园区攻略 / 我的。

现有为：首页 / 景点 / 攻略 / 服务 / 我的。四栏导航已落地：复用原 product/index 页面作为景点导览目录，明确展示景点详情和交通信息，不显示地图或定位按钮。服务页保留原路由，改为普通页面，首页及个人中心均保留入口。首页服务入口使用普通页面跳转，保留返回路径；原景点和攻略路由未更改。

## 统一视觉约定

Token 文件：`miniprogram/projects/TRIP1/style/ui_tokens.wxss`。通过 app.wxss 与项目皮肤应用到全站；详情、列表、服务、个人中心和后台分别使用共享视觉层。

- 主色 #116b60；浅绿 #eaf4f0；正文 #182f2b；辅助文字 #687b76；背景 #f5f8f6；白色表面 #ffffff；边线 #e4ece7。
- 正文使用系统中文无衬线字体；摄影标题使用系统宋体衬线，字体无需网络加载。
- 正文 28rpx；辅助 24rpx；栏目标题 36rpx；主视觉标题 60rpx。
- 页面边距 32rpx；栏目间隔 48rpx；卡片圆角 24rpx；小图圆角 16rpx。
- 沿用项目已有 icon 字体，首页图标统一深绿线性视觉；不新增另一套图标依赖。
- 主视觉为大幅景区摄影，正文左对齐；仅摄影可叠渐变遮罩，其余采用白色表面和留白。

## 验证

- 首页 JavaScript 语法检查通过。
- 使用已安装微信开发者工具的 WXML/WXSS 编译器编译通过。
- 本地模拟验证：接口名与参数、分类展示、空状态、失败恢复、轮播索引、自定义导航安全区、19 个静态页面入口通过。
- 微信开发者工具实际预览已显示新版首页，并展示云端真实内容；审查后替换了原先两张装饰占位图为仓库内景区摄影，同时修正了动态提示的分类。
- 最后这两处修正已通过编译及本地校验；最终模拟器截图与逐项实机点击尚待复核。预览环境显示已有警告，未据此声称整个项目无警告。
- 未测试提交预约、拨号、后台写入或第三方服务，也不声称这些写入流程已端到端验证。

## 用户确认后的业务范围修正

- 景区免费开放，不对接支付，不提供订单、景点预约、停车预约或理赔。
- 首页原预约大卡片改为免费景点探索，便捷入口的停车预约替换为现有星级导游信息。
- 个人中心移除“我的预约”；保留个人资料、收藏、浏览记录。
- 已检查全项目无反馈实现，按用户授权新增客户反馈页面与 mcloud 路由。三个用户入口统一连接新页面，后台可查看与回复。
- 旧预约路由与代码暂保留，无用户侧入口；后台主入口改为客户反馈。
