# WeTravel 本地后端测试用例

## 1. 测试范围

本用例集验证前端业务与本地后端、SQLite 表字段之间的对应关系。测试只使用 `127.0.0.1:8787` 和 `local/data/wetravel.sqlite3`，不连接微信云数据库或线上 MySQL。

覆盖模块：景区、景点、攻略、资讯、商户、全景、首页配置、用户、收藏、反馈、预约、后台认证、管理员统计、SQLite 约束和云环境防误连。

## 2. 数据库结构用例

| 编号 | 场景 | 操作 | 预期结果 |
| --- | --- | --- | --- |
| DB-01 | 标准业务表 | 初始化 SQLite 后查询 `sqlite_master` | 存在 20 张 v2 业务表，不存在旧 `product/album/meet/join/day` 表 |
| DB-02 | 初始化幂等 | 连续执行两次 schema、seed、demo | 分类、演示内容不重复，外键检查通过 |
| DB-03 | JSON 字段 | 向 JSON 字段写入非法 JSON | 数据库拒绝写入 |
| DB-04 | 分类外键 | 景点引用不存在的分类 | 数据库拒绝写入 |
| DB-05 | 攻略景点项目隔离 | 攻略关联其他项目景点 | 触发器拒绝写入 |
| DB-06 | 预约关系一致性 | booking 使用不属于目标预约的 slot | 触发器拒绝写入 |
| DB-07 | 防重复预约 | 同一用户重复预约同一时段 | 活跃预约唯一索引拒绝第二条记录 |
| DB-08 | 取消后重约 | 将原预约状态改为取消，再次预约 | 允许重新创建活跃预约 |
| DB-09 | 时段容量 | 活跃预约数达到 capacity 后继续预约 | 容量触发器拒绝写入 |
| DB-10 | 空手机号 | 多个未填写手机号的本地游客注册 | 允许；只有非空手机号执行唯一约束 |

## 3. 内容管理用例

| 编号 | 场景 | 操作 | 预期结果 |
| --- | --- | --- | --- |
| CMS-01 | 草稿隔离 | 管理端保存景点草稿，游客端搜索 | 游客端不可见 |
| CMS-02 | 发布 | 将草稿状态改为 `published` | 游客列表和详情可见 |
| CMS-03 | 下架/删除 | 状态改为 `offline` 或 `deleted` | 游客接口不返回记录 |
| CMS-04 | 分类 | 新增、编辑、发布景点/攻略/资讯分类 | 内容只能引用同模块有效分类 |
| CMS-05 | 攻略路线 | 保存有序景点数组 | `guide_spots.position` 与前端顺序一致 |
| CMS-06 | 图片上传 | 上传 PNG/JPEG Base64 | 文件写入 `local/uploads`，返回本地媒体 URL |
| CMS-07 | 非图片数据 | 上传伪造或超过 5MB 的内容 | API 返回数据校验错误 |
| CMS-08 | 首页草稿 | 保存首页草稿但不发布 | 游客首页继续使用旧发布版本 |
| CMS-09 | 首页发布 | 发布已保存的首页草稿 | 游客首页读取新配置 |

## 4. 用户与反馈用例

| 编号 | 场景 | 操作 | 预期结果 |
| --- | --- | --- | --- |
| USER-01 | 本地游客创建 | 不同 token 首次调用用户接口 | 分别生成独立用户记录 |
| USER-02 | 注册资料 | 提交昵称、手机号和动态表单 | `users` 对应字段更新，个人详情可读取 |
| USER-03 | 收藏切换 | 收藏、查询、取消收藏 | 状态依次为 1、1、0 |
| USER-04 | 数据隔离 | 用户 B 查询用户 A 的反馈/收藏 | 不返回用户 A 的数据 |
| FB-01 | 反馈图片 | 以 requestId 上传图片 | 文件路径绑定当前用户与 requestId |
| FB-02 | 幂等提交 | 同一用户以相同 requestId 重试 | 返回同一反馈，不重复插入 |
| FB-03 | 管理回复 | 管理员回复反馈 | 状态变为已处理，游客端可读回复 |
| FB-04 | 未授权处理 | 无管理员 token 调用处理接口 | 返回 2401 |

## 5. 预约用例

| 编号 | 场景 | 操作 | 预期结果 |
| --- | --- | --- | --- |
| RSV-01 | 后台新增 | 新增预约项目、日期和时段 | 分别落入 `reservations/reservation_days/reservation_slots` |
| RSV-02 | 后台编辑 | 修改标题、表单、日期、时段与容量 | 标准化表结构同步更新 |
| RSV-03 | 游客预约 | 选择 reservationId 和 timeMark 提交 | booking 同时匹配项目、日期、时段和用户 |
| RSV-04 | 个人详情 | 当前用户读取 booking | 返回标题、日期、时间、状态和核销码 |
| RSV-05 | 取消 | 当前用户取消未签到预约 | 状态由 1 变为 10 |
| RSV-06 | 签到 | 当前用户用时段签到码签到 | `checked_in=1` 并记录 `checked_in_at` |
| RSV-07 | 后台关闭 | 管理员把预约状态改为 10 | 游客列表不再展示 |
| RSV-08 | 有记录删除保护 | 删除已有 booking 的预约项目 | API 拒绝，提示改为关闭 |

## 6. 安全与运行用例

| 编号 | 场景 | 操作 | 预期结果 |
| --- | --- | --- | --- |
| SEC-01 | 云环境防误连 | `CLOUD_ID` 为空时调用云实例 | 立即报错，不选择默认云环境 |
| SEC-02 | 本地前端适配 | `CLOUD_ID` 为空时调用业务接口 | 使用 `LOCAL_API_BASE` 的 `/api` |
| SEC-03 | 管理认证 | 无 token 或过期 token 调用管理接口 | 返回 2401 |
| SEC-04 | 路径穿越 | 请求 `/media/../...` | 返回 404，不读取上传目录之外文件 |
| SEC-05 | 完整性 | 执行 `PRAGMA integrity_check` | 返回 `ok` |
| SEC-06 | 外键 | 执行 `PRAGMA foreign_key_check` | 返回空集合 |

## 7. 执行方法

```bash
npm test
npm run test:business
```

`npm test` 使用临时数据库完成自动化单元和集成测试；`npm run test:business` 请求正在运行的本地 HTTP 服务，并在结束时清理本轮验收数据。
