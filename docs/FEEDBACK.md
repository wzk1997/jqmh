# 客户反馈

景区免费开放，无预约、订单、支付和理赔。用户授权新增反馈页面与云端实现后，功能沿用项目现有 `mcloud` 云函数，不新增独立运行时或第三方服务。

## 功能

- 首页“客户反馈”、公共服务页、个人中心连接同一页面。
- 类型：游玩体验、环境设施、服务建议、其他反馈。
- 内容5至500字；联系电话选填；最多3张JPG/PNG，每张不超过5MB。
- 游客无需另外注册，身份取自云函数可信的微信 OPENID，经原框架带项目标识。
- 只显示当前游客提交的反馈；可查看管理员回复。
- 管理员通过后台“客户反馈”查看、回复；回复后显示“已回复”。
- 提交失败保留内容与已上传图片；相同提交标识对应固定文档ID，防止并发或网络重试产生重复反馈。

## 云端接口

| 路由 | 用途 | 身份限制 |
| --- | --- | --- |
| feedback/submit | 提交反馈 | 云函数可信游客身份，不接受客户端指定归属或状态 |
| feedback/my_list | 每页10条个人反馈 | 服务端绑定游客与项目 |
| admin/feedback_list | 每页10条全部反馈 | 原有管理员 token 校验与项目隔离 |
| admin/feedback_reply | 保存回复、标记已回复 | 原有管理员 token 校验，遵循项目 demo 限制 |

数据模型：`cloudfunctions/mcloud/project/TRIP1/model/feedback_model.js`。集合名遵循已有 `COLLECTION_PRFIX` 配置，通常为 `bx_feedback`。首次调用反馈接口时创建新集合，不改动其他集合。图片上传至 `<PID>/feedback/<requestId>/`。服务端检查图片路径、实际格式、大小，并沿用项目已有的内容审核开关。

## 上线步骤

代码已经写入本地，尚未部署云端或写入线上数据。

1. 在微信开发者工具将现有 `cloudfunctions/mcloud` 上传并部署（云端安装依赖），使用项目原云环境。只更新前端不能启用新接口。
2. 新反馈集合采用禁止小程序客户端直接读写的权限；游客和管理员统一通过已校验身份的云函数访问。部署环境中首次调用可创建集合，亦可按配置前缀提前创建。
3. 云存储反馈图片保持私有授权访问；游客访问自己上传的图片，管理员通过服务端授权的临时图片链接访问。列表接口仅在游客归属或管理员身份校验后签发临时链接。不要将反馈附件目录设置为公开可读。原项目存储权限不能从本地源码确认，需在云控制台核对，并验证管理员预览是否与现有规则兼容。
4. 使用真实游客测试提交文字/图片、失败重试、查看自己的记录；用另一游客确认数据隔离；管理员查看并回复，再由原游客确认回复。

## 本地验证

`node --test tests/feedback.test.cjs`

覆盖：输入校验、空图片、图片格式与大小、可信身份、项目隔离、重复提交、管理员授权、回复更新、前端失败恢复、并发提交保护、路由注册，以及真实ORM字段清洗。WXML/WXSS 编译与JS语法检查另行通过。

本机 Node 25 直接加载项目旧版 wx-server-sdk 的传递依赖会遇到 `SlowBuffer` 兼容错误。因此本地测试对云SDK/数据库做隔离，保留真实业务逻辑、校验器和ORM；未将模拟通过称为云端端到端通过。未升级项目现有SDK和依赖锁文件。
